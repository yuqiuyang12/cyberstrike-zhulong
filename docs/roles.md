# 角色可见性:注册 ≠ 可调用

## 事实

平台内置工具注册后,**执行者只能看到 roles/*.yaml 的 `tools` 列表里列出的工具**。
`zl_chain_open / zl_chain_attempt / zl_chain_close / zl_chain_list` 四个工具
若不在角色白名单里,模型**根本看不见**,表现为"模型从不调链工具、7 分钟 chain=0"。

## 现役做法

给 19 个含 `record_vulnerability` 的角色各加 4 个工具(按字母序插入):

```
API安全测试 30→34 · CTF 41→45 · Web应用扫描 60→64 · Web框架测试 40→44
二进制分析 38→42 · 云安全审计 26→30 · 全栈渗透 167→171 · 后渗透测试 50→54
容器安全 20→24 · 开发ai专员 17→21 · 快速摸排 50→54 · 数字取证 30→34
渗透测试 154→158 · 红队模式 150→154 · 综合漏洞扫描 60→64 · 自我优化专员 29→33 · 默认 30→34
(另含 SRC挖洞专家 / 0day原创漏洞专家，合计 19 个文件)
```

## 热更方式

`PUT /api/roles/<name>`(内存 + yaml 双写),免重启;改完用
`GET /api/roles` 复核 `tools` 长度与是否含 `zl_chain_*`。

> 注意:磁盘改 yaml 后若 UI 里保存过角色,平台会用内存态回写覆盖磁盘 —— 走 API 最稳。
