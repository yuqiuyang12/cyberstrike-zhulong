# KB-BB-05 · 利用链阶梯与证伪纪律(信息泄露是燃料,不是终点)

> **触发**:任何一次"已确认漏洞"之后 —— 尤其是信息泄露类(异常堆栈、源码/模板、内网地址、接口契约、版本指纹)已经落库,但还没打到数据读取/认证绕过/写入/执行/横向。
> **判据**:一条链只有在「打穿到某个危害台阶」或「同一台阶连试 ≥3 个不同变体且拿到确定性拦截原始报文」时才能关;closed ≠ 交卷。
> **误判**:①把"报了一条 low/medium 信息泄露"当成本轮成果;②把一次 500/403 当"链已闭合";③在**同一轮里**既推进链又收口交卷;④把扫描器/知识库检索命中当链条证据。

---

## 一、为什么必须阶梯化

真实环境里,**单独一条信息泄露通常不构成高危**;它的价值在于给下一阶提供"燃料":类名/版本/内部地址/接口契约/过滤规则。评测与实战的分数差,90% 出在"燃料有没有被烧掉":

- 拿到 Spring Boot 完整异常堆栈 → 知道类名、框架版本、防火墙实现 → 才能定向选 actuator / 反序列化 / SpEL 路线;
- 拿到 nginx `/api/` 前缀绕过 → 才有机会触达上游内部 API(收益取决于上游有没有未授权接口,而不是绕过本身);
- 拿到 FreeMarker 模板源码 → 知道指令集/变量名 → 才能构造 SSTI 求值;
- 拿到 ES 搜索 API 契约 → 才知道 `q` 参数进的是查询串(而不是过滤条件)→ 才能做布尔/长度差分。

**结论:信息泄露类发现必须落成"链",而不是"漏洞条目的终点"。**

---

## 二、台阶定义(0→6,只升不降)

| rung | 名称 | 达标证据(必须落盘原始报文) |
|---|---|---|
| 0 | 已确认(Confirmed) | 复现请求 + 响应,能稳定重放 |
| 1 | 读到敏感数据 | 读到不属于公开面的内容:配置/密钥/他人业务数据/内部拓扑;要能指出"哪一行不该给我" |
| 2 | 认证/授权绕过 | 未登录或用低权账号拿到需登录/高权的**功能或数据**;仅"接口存在"不算 |
| 3 | 写入 | 数据/配置/状态被真实改变(前后对照) |
| 4 | 上传/落地 | 文件/载荷落到目标并可被访问或引用 |
| 5 | 执行 | 命令/模板/表达式被真实执行(OOB 回连、落点文件、输出回显任一) |
| 6 | 横向 | 从该点取得下一跳凭据或控制面 |

记账口径:**每条链只记"当前最高台阶"**,每次尝试都写一行 attempt(payload + 报文路径 + verdict),不写"大概可能"。

## 三、四个高频"燃料→台阶"路线(照抄后必须按现场改造)

### 3.1 Spring Boot 异常堆栈 → actuator / env / heapdump → 反序列化

1. 从堆栈里提取:`StrictHttpFirewall`(说明开了 firewall)、`FilterChainProxy`、`NioEndpoint`、内部包名(`com.xxx.*`)、框架版本线索;
2. 定向打 `/actuator`、`/actuator/env`、`/actuator/heapdump`、`/actuator/mappings`;被 nginx deny 时按 3.2 的绕过矩阵逐条试;
3. heapdump 拿下 → 找 datasource 密码/密钥 → 再打 DB/内网;
4. 有 `/actuator/gateway` 或 `/env` 可写 → 走 SpEL/`spring.cloud.gateway` 远程加载 → 执行;
5. 有反序列化面(Shiro/fastjson/JNDI)→ 用 `ysoserial` 出链 + 自建 LDAP/HTTP 回连验证(OOB 必须有回连记录)。

> 判死口径:全路径矩阵(actuator 家族 × 编码变体 × 方法)× 全部 404/403/Nginx 默认页,且**每条都留了原始响应**;仅"试了两个 404"不算。

### 3.2 nginx 前缀/bypass → 上游内部 API

| 变体族 | 示例 | 观察点 |
|---|---|---|
| 点分号 | `/.;/api/x`、`/api/.;/x` | nginx 归一化 vs 上游防火墙(Spring `StrictHttpFirewall` 会拒 `;`) |
| 编码斜杠 | `/api%2F x`、`/api%252Fx` | 用 `curl --path-as-is`,避免客户端二次编码 |
| 双写/多点 | `//api/x`、`/./api/x`、`/x/../api/x` | 200 与 403 的分界 |
| 头覆盖 | `X-Original-URL`、`X-Rewrite-URL`、`X-Forwarded-Prefix` | 上游是否用头路由 |
| 大小写/尾点 | `/API/x`、`/api/x.`、`/api/x%00` | 规则是否大小写敏感 |

判据:**能拿到 200 + 业务数据**才算穿透成功;拿到 500 全栈只说明"请求到了上游",不说明"穿透成功"。
拿到 500 全栈时,把它当 rung 0 的燃料,继续找"既不触发上游防火墙、又能过 nginx 规则"的编码 —— 这是**变体穷举**问题,不是"不可利用"。

### 3.3 模板/源码泄露 → SSTI / 源码审计 → RCE

1. FreeMarker/Velocity/Thymeleaf 源码可读 → 找用户可控变量进入模板的入口(`?alias=`、`?q=`、路径段);
2. 构造 `${7*7}` / `<#assign>` 观测求值;被转义时换 `${...?new()}` 链;
3. 求值成立 → 走 `Execute`/`freemarker.template.utility.Execute` 或 `ObjectConstructor` 出 RCE;
4. 同时把源码当审计材料:找上传点、内部接口、硬编码密钥(它们本身就是下一阶燃料)。

### 3.4 搜索/查询接口契约 → 注入 → 数据外带

1. 从契约判断参数语义:`q` 是查询串还是过滤条件、是否 `isOperatorAnd` 之类的 DSL 开关;
2. 布尔/长度差分优先(`q=*` vs `q=zzz` vs `q=a*`),再试语法注入(`"`, `\`, `AND`/`OR`、`script` 字段);
3. 有 `_source`/`fields` 参数就可能直接外带字段;有 `script_fields` 就可能 RCE(ES 版本相关);
4. 外带必须闭环:命中数变化 + 具体数据回显,二者缺一不算。

## 四、证伪纪律(关链的唯一合法姿势)

允许 `blocked` 的三要素,缺一不可:

1. **枚举空间**:试了哪些变体(列全)、多少个、用什么方法;
2. **确定性拦截证据**:拦截方的原始响应(状态码 + 关键报错原文 + 时间),不是"看起来被拦";
3. **未覆盖面**:明确写出"还有哪一类没试、为什么"(例如需要内网跳板/需要测试账号/W3 未授权),而不是"不可利用"。

❌ 反例:"`/.;/actuator/env` 返回 500,链闭合" → 实际只证明"带分号的路径被上游防火墙拒",没证明"其他编码不过 nginx"。
✅ 正例:"分号族 9 个变体全被 `StrictHttpFirewall` 拒(报文 evid/xx.txt),编码斜杠族 12 个变体全部 403(evid/yy.txt);未覆盖面:需要内网出口才能验证上游是否监听 8080"。

## 五、与平台工具的对齐(必须用,不许口述)

| 动作 | 工具 | 说明 |
|---|---|---|
| 开链 | `zl_chain_open` | 每个 confirmed 漏洞(critical/high/medium)一条;new finding 自动挂链 |
| 记尝试 | `zl_chain_attempt` | 每个变体一行:rung + payload + 报文绝对路径 + verdict(progress/exploited/rejected/blocked) |
| 关链 | `zl_chain_close` | `exploited` 或 `blocked`(blocked 必须带拦截报文路径) |
| 看链 | `zl_chain_list` | 开工先看,挑最深的 open 链推进 |
| 交卷 | `deliver_gate` | 首行必须是 `GATE=PASS`;**open 链未清零 = 不许交卷** |

## 六、自检 6 问(交卷前,任一答不上就别交)

1. 本轮推进了哪条链?到第几阶?
2. 每次尝试的原始报文在哪(绝对路径)?
3. 被判 blocked 的那一阶,拦截方的**原文**是什么?
4. 还有哪一类变体没试?为什么(需要人/需要内网/需要授权)?—— 写进"人工待办",不写"不可利用"。
5. 这条链的下一阶是什么?谁能在下一轮接手?
6. 如果这条链打穿,攻击者**实际拿到什么**?这句话要能直接写进报告影响栏。
